# AGENT.md - Restic File System Plugin for Total Commander (WFX)

Technical specification, operational requirements, compiler hardening rules, and architectural guidelines for developing the Total Commander Restic plugin in standard C (C11).

---

## 1. Project Goal

Build a **File System Plugin (WFX)** extension for **Total Commander** written strictly in **pure standard C (C11)** (no C++ or other languages).

The primary goal is interactive, read-only browsing of **Restic** backup repositories ([https://restic.net](https://restic.net)), allowing users to navigate seamlessly across configured repositories, snapshots, and directory trees directly within Total Commander's dual-pane interface.

**Current scope:** read-only browsing **plus extraction** of files and whole folders through Total Commander's native copy (`F5`), viewer (`F3`) and Quick View (`Ctrl+Q`). Repository modification (upload, delete, move/rename, mkdir) is deliberately out of scope and not exported.

---

## 2. Core Architectural Decisions

1. **Interface Choice: WFX (File System Extension) instead of WCX (Packer)**
   - *Rationale:* The WCX archive model requires sequential, exhaustive enumeration of every file in an archive upon opening (`OpenArchive` / `ReadHeader` loop), freezing the UI on repositories containing hundreds of thousands of files. The WFX model enables lazy, on-demand directory-by-directory loading through the `FsFindFirstW` / `FsFindNextW` / `FsFindClose` lifecycle.

2. **Native CLI Integration**
   - No direct parsing of Restic's proprietary binary repository formats.
   - Invokes `restic.exe` as a hidden child process (`CREATE_NO_WINDOW`) via Win32 API (`CreateProcessW`).

3. **JSON & NDJSON Parsing**
   - A minimal, strict, read-only JSON reader of the project's own (`src/json.c`, `src/json.h`, ~370 lines), written for exactly what Restic prints. No third-party JSON library: the plugin parses untrusted repository content inside Total Commander's process, and a reader that does only what is needed is code that can be read in full.
   - Strict RFC 8259 (no comments, trailing commas, leading zeros), nesting limited to `JSON_MAX_DEPTH` (64), strings containing `\u0000` rejected so every decoded string is a plain C string, lone surrogate escapes decoded as U+FFFD. Integers are read exactly (`json_u64`), so file sizes above 2^53 are not rounded through a `double`. One arena per document: a single `json_free()` releases everything.
   - Portable C11 without Win32: `src/tests/test_json.c` builds with any hosted compiler (e.g. `gcc -fsanitize=address,undefined`), not only MSVC.
   - Verified beyond the unit tests: the full JSONTestSuite (all n_ rejected, all y_ accepted except the two with `\u0000`), differential testing against Python's `json`, and coverage-guided fuzzing (`src/tests/fuzz_json.c`). Re-run the fuzz target after any change to `json.c`; likewise `src/tests/fuzz_snapshot.c` after changes to `snapshot_tree.c`, `snapshot_index.c` or `timestamp.c`, which parse restic's output into the browsing structures.
   - Uses line-by-line NDJSON streaming/parsing for `restic ls --json` output.

4. **Caching Policy**
   - Measured first (restic 0.19.1, 200 000-file snapshot, local repository / REST server with 40 ms RTT): every restic run costs ~1.0 s / ~1.3 s before it prints anything (scrypt key derivation from the password, then loading the index), and listing a folder together with ten sibling folders costs the same as one folder; the whole snapshot (`ls` without a path) takes 8 s and prints 87 MB of NDJSON. The cost is per process, not per folder.
   - So, in memory only (nothing on disk): each repository's snapshot list (as the restic mount tree) is cached and re-read in the background once older than 60 s, like `restic mount` re-reads it, while the old one stays in use (section 4); and entering a snapshot - at any depth - starts one background `restic ls --json --no-lock <id>` of the whole snapshot, streamed line by line into a compact index (`src/snapshot_index.c`, ~90 bytes per entry), after which every folder of that snapshot is listed without restic. Until the index is ready each folder is listed by its own `restic ls` as before.
   - Everything cached for a repository lives only as long as its cached password and is used only with it.
   - Accepted residual risk: the cached names, sizes and times of a repository's files sit unencrypted in Total Commander's memory (they are what the panels show anyway) until the password goes; they are never written to disk. Passwords stay encrypted as before.

5. **Credential Lifecycle**
   - No passwords are stored on disk (neither in `TCResticBrowser.ini` nor in external files).
   - Credentials are requested at runtime when entering a repository via Total Commander's `RequestProcW` (`RT_Password`) callback.
   - Per-repository exceptions live in a `[Repository: <alias>]` section (3.2): `PasswordFile` / `PasswordCommand` let restic read the password itself (no prompt; the plugin never sees it), `AWS_ACCESS_KEY_ID` makes the plugin prompt for the S3 secret access key (title `<alias> - S3 secret access key`, before the password), which is cached exactly like a password; `AWS_SHARED_CREDENTIALS_FILE` and `AWS_PROFILE` point restic at a credentials file. Secrets are never read from the INI.
   - Credentials remain in RAM only, in a small per-repository session table (8 slots, so two panels can browse two repositories without being re-prompted). Entries are encrypted (`CryptProtectMemory`) and wiped on wrong password, on `FsInitW`, on DLL unload, after `PasswordTimeoutSeconds` (default 30 minutes), through the `🗑 Forget N Passwords` root entry and through the connections toolbar's Disconnect (`FsDisconnectW`); the least recently cached slot is recycled when the table is full.

## 3. Configuration: `TCResticBrowser.ini`

### 3.1 INI File Path Resolution

The first existing file is used in full - keys are never merged across files. This order is shared with the author's other Total Commander plugins (TCOfficeView, TCNewPlus); keep it identical.

1. **Per-user override:** `%APPDATA%\GHISLER\TCResticBrowser.ini` (`config_get_user_ini_path()`, built from the `APPDATA` environment variable on every lookup).
2. **System-wide default:** `<plugin_dir>\TCResticBrowser.ini`, next to the plugin DLL, resolved at load time in `DllMain` via `GetModuleFileNameW`. This is where the commented sample ships, so a plugin upgrade overwrites it; user settings belong in the per-user file.
3. **`DefaultIniName` is ignored:** `FsSetDefaultParams` does nothing. Total Commander's own settings folder is usually `%APPDATA%\GHISLER` anyway; a deviating one (portable install, redirected `wincmd.ini`) is deliberately not consulted, for the same lookup as the sibling plugins.
4. **Tests must isolate `%APPDATA%`:** `test_config` and `test_plugin_dll` point `APPDATA` at an empty temporary directory first, otherwise a developer's real per-user INI would change the results.
5. **No Auto-Creation at Runtime (Sample Template in Repo):** the plugin DLL never creates or modifies `TCResticBrowser.ini` on disk. If neither file exists: the root listing (`\`) returns `ERROR_NO_MORE_FILES` (empty folder), `\<Alias>[...]` listings return `ERROR_PATH_NOT_FOUND`, and `FsGetFileW` returns `FS_FILE_NOTFOUND`; no password prompt and no popup are shown. A fully commented sample `src\TCResticBrowser.ini` is tracked in the repository, staged next to the built DLL by CMake, and shipped in the release ZIP.

### 3.2 INI File Structure

INI key-value syntax, read by the plugin's own reader in `config.c` (not `GetPrivateProfile*`): `[Section]` names and keys compare case-insensitively, lines starting with `;` or `#` are comments, keys and values are trimmed and a value is unquoted (`"..."` or `'...'`), CRLF, LF and CR line breaks are accepted. `ResticPath` takes its first occurrence in `[Settings]`; a repeated alias in `[Repositories]` updates the earlier one. Entries longer than the fixed buffers (alias `MAX_PATH`, target `CONFIG_MAX_PATH`) are skipped, never truncated, and a file above `CONFIG_MAX_INI_BYTES` (4 MiB) is not read.

```ini
[Settings]
; Optional path to restic.exe (if empty, checks plugin folder then system PATH)
ResticPath=restic.exe
; Optional Network Neighborhood root name (default "TCResticBrowser")
RootName=Backups
; Optional memory for whole-snapshot listings in MiB (default 512, 0 = off)
SnapshotCacheMB=512
; Optional age of the snapshot list that makes it re-read in the background (default 60)
SnapshotListRefreshSeconds=60
; Optional Total Commander connections toolbar with a log of what the plugin does and what takes time (default yes)
ConnectionLog=no
; Optional snapshot folder name format (default YYYY-MM-DD_hh-mm-ss)
SnapshotTimeFormat=YYYY-MM-DDThh.mm.ss
; Optional field separator of snapshots.csv: , ; | or tab (default: the Windows list separator)
CsvSeparator=;

[Repositories]
; <Display_Alias>=<Restic_Repository_Target>
LocalBackup=D:\Backups\ResticRepo
ServerLinux=rest:https://backup.lan:8000/
CloudS3=s3:s3.us-east-1.amazonaws.com/company-backup/restic
NAS_SMB=\\nas\share\restic_repo

[Repository: CloudS3]
; restic reads the password itself: PasswordFile=<file> or PasswordCommand=<program> (no prompt)
PasswordCommand="C:\Tools\get-password.exe" --name backup
; S3 settings as restic's environment; the secret key is asked for at runtime
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
;AWS_DEFAULT_REGION=eu-central-1
; Any restic extended option, passed as -o s3.bucket-lookup=dns
;s3.bucket-lookup=dns
;AWS_SHARED_CREDENTIALS_FILE=C:\Users\me\.aws\credentials
;AWS_PROFILE=backup
```

**`[Repository: <alias>]` sections (`config.c`, `read_repo_setting`):** settings of one repository, matched to the `[Repositories]` alias ignoring ASCII case; the section name ends at the last `]` when only whitespace follows it (an alias may contain `]`), the section may come before `[Repositories]` (applied after the whole file is read), each key's first occurrence wins also across repeated sections, empty values mean not set, unknown keys and sections for unknown aliases are ignored. Values are resolved at load time into `ResticRepoEntry`: `PasswordFile` and `AWS_SHARED_CREDENTIALS_FILE` like `ResticPath` (full path or relative to the plugin folder, drive- or root-relative refused, must exist); `PasswordCommand` without quote characters is the program's path (resolved like `ResticPath`, bare names in the plugin folder then `PATH`) and is passed in double quotes, with quotes it is a command line checked against restic's own splitter (`backend.SplitShellStrings`, ported as `split_restic_command`: `"`/`'` group, a quote after a backslash is literal, and **a backslash outside quotes separates arguments**, so unquoted Windows paths are refused), its program a full path that exists or a bare name; the INI reader's quote stripping is undone for it (`IniReader.unquoted`). The S3 environment variables restic documents (`doc/075_scripting.rst`) except the secret ones - `AWS_ACCESS_KEY_ID`, `AWS_DEFAULT_REGION`, `AWS_PROFILE`, `AWS_SHARED_CREDENTIALS_FILE` (a file, resolved as above) and the six `RESTIC_AWS_ASSUME_ROLE_*` (`REPO_KEYS`) - are kept under restic's names in `ResticRepoEntry.environment`, a `NAME=value\0...\0\0` block (`config_repo_env_value()` reads one); `AWS_SECRET_ACCESS_KEY` is prompted for, `AWS_SESSION_TOKEN` is left to the credentials file (temporary, secret). Any `<backend>.<option>` key (`is_option_key`) is a restic extended option, lowercased as restic does, kept in `ResticRepoEntry.options` and passed as `-o "<key>=<value>"` before the command (`option_arguments()` in `restic_cli.c`, also for `restic dump`); restic validates names and values (`option ... is not known`) and refuses repeated keys, so the first occurrence wins here. The INI reader's quote removal is undone for an option value that still contains that quote. The four options restic splits into a command line itself (`backend.SplitShellStrings`) follow the `PasswordCommand` rules (`resolve_command()`): `rclone.program` and `sftp.command` are a plain path (resolved, then quoted) or a checked command line kept as written, `rclone.args` and `sftp.args` arguments kept as written, an unquoted backslash refused. **restic's `-o` is a pflag string slice, which parses each value as a line of CSV**: a quote inside a value fails ("bare `"` in non-quoted-field") and a comma splits it into two options, so `option_arguments()` makes any `key=value` with a quote, comma or line break one quoted CSV field (inner quotes doubled) before the command-line quoting; verified with `rclone.program="Z:\...\rclone.exe"` under restic 0.19.1. Plain values must not contain control characters. Anything unusable sets `settings_error` (`<key>=<value> (set in [Repository: <alias>] of <ini>) <reason>`), which `repository_usable()` in `main.c` shows before any prompt or restic run. `PasswordFile` together with `PasswordCommand` is deliberately not resolved by the plugin: both go to restic, which refuses the pair, exactly as on its own command line.

### 3.3 Restic Binary Resolution Order

1. A non-empty `ResticPath` under `[Settings]` (first occurrence) is used or nothing is: a full path must exist, a relative one is joined to the plugin directory, and a bare name (`.exe` added when it has no extension) is looked up in the plugin directory, then in `PATH`. A missing or unusable configured binary is an error; steps 2-3 are **not** tried, so the user never runs a different `restic.exe` without knowing it.
2. Without `ResticPath`: local `restic.exe` binary located in the plugin directory (`<plugin_dir>\restic.exe`).
3. Then `restic.exe` found in the directories listed in the `PATH` environment variable.

Rules enforced by `config_resolve_restic_path()`:
- **The current directory is never searched.** `SearchPathW` and bare-name `CreateProcess` lookups include the process working directory (which follows the Total Commander panel), so a `restic.exe` planted in a browsed folder could hijack the plugin. `PATH` is therefore walked manually (`find_in_path_env`): empty entries and entries that are not absolute (`.`, `bin`, `C:tools`, an unexpanded `%SystemRoot%\...`) are skipped, quoted entries are unquoted, an extension-less name gets `.exe` appended, and the hit is returned as an absolute path.
- Only absolute paths (`config_is_absolute_path`: `X:\...` or `\\server\...`) are ever used. A relative `ResticPath` is joined to the plugin folder; a drive-relative (`C:restic.exe`) or root-relative (`\tools\restic.exe`) one is refused. A relative `%APPDATA%` disables the per-user INI.
- When nothing is found the function returns `FALSE`, the bare name `restic.exe` and a user-facing reason (`ResticConfig.restic_path_error`: the setting as written, the INI file, the resolved path tried, or "restic.exe not found" without `ResticPath`). `restic_exec_command()` and `restic_dump_file()` refuse every path that is not absolute (`RESTIC_ERR_SPAWN_FAILED`), so the caller (`restic_path_usable()` in `main.c`, before any password prompt) shows that reason instead of spawning anything.
- A `ResticPath` too long for the path buffers is an error too: paths are never truncated, and `join_path` checks the length before `wcscat_s`, whose overflow handler would terminate Total Commander.

### 3.4 INI File Encoding

UTF-8 by default, like the author's sibling plugins; a UTF-8, UTF-16 LE or UTF-16 BE byte-order mark is honoured (`read_ini_text`). A BOM-less file that is not valid UTF-8 is decoded in the ANSI code page, because the 1.x plugin read its INI through `GetPrivateProfile*W` and documented ANSI. That API is deliberately not used: it reads a BOM-less file as ANSI and garbles UTF-8 paths. Alias lookup (`_wcsicmp`) folds ASCII case only; Total Commander always passes back the exact name the plugin listed.

### 3.5 Diagnostic Log (`[Logging] LogPath`, `src/log.c`)

Off by default, like TCOfficeView. `LogPath` (first occurrence in `[Logging]`) is applied by every `config_load()` through `log_configure()`, so it follows the INI without a restart; environment variables are expanded, a relative or empty path means off, missing parent directories are created. Each line is opened, appended as UTF-8 (no BOM) with a local time / pid / tid prefix, and closed, so the file is never locked. Logged: `FsInitW` (version, bitness, plugin dir), the effective configuration on every root listing (including `SnapshotTimeFormat`, flagged when the configured one is unusable, `SnapshotCacheMB` with the limit applied when 32-bit Total Commander caps it, and the effective `CsvSeparator`), each `restic` command line with its exit code, duration, result and stderr, the background snapshot-list re-reads and whole-snapshot listings (started, read with entry count, memory and duration, not kept and why, dropped to make room), password prompts (**length only**, plus the `restic_describe_password` note when the entry starts or ends with whitespace or contains invisible characters), copies, and every error dialog. **Never log a password or `RESTIC_PASSWORD`;** repository targets go through `log_redact_target()`, which masks everything between `scheme://` and the **last** `@` (over-masking a path is preferred to logging a password that contains an unencoded `/`). `test_plugin_dll` asserts that no password, right or wrong, reaches the log.

## 4. Virtual Navigation Hierarchy

Total Commander passes backslash-delimited paths rooted at `\`. The plugin maps virtual paths as follows:

| Level | WFX Path | Data Source | Action / Presentation |
| --- | --- | --- | --- |
| **0. Root** | `\` | `[Repositories]` section of `TCResticBrowser.ini` | While passwords are cached, returns the virtual file `🗑 Forget N Password(s)` (`FORGET_ENTRY_PREFIX` + count, U+1F5D1) first; then each configured alias (e.g., `LocalBackup`, `ServerLinux`) as a virtual directory (`FILE_ATTRIBUTE_DIRECTORY`); an alias starting with the forget prefix is not listed (nor reachable through `FsFindFirstW`/`FsGetFileW`). With no INI or no repositories the root stays empty, except for the forget entry while passwords are still cached. |
| **1. Repository** | `\<RepoAlias>\[ids\|snapshots\|hosts\<host>\|tags\<tag>\]` | `restic snapshots --json --no-lock` (cached, see below) | The folder tree `restic mount` presents (`src/snapshot_tree.c`): `ids\<short id>`, `snapshots\<time>`, `hosts\<host>\<time>`, `tags\<tag>\<time>`, plus `latest` in every folder of times (`snapshots`: newest of the repository, any host; `hosts\<host>`, `tags\<tag>`: newest of that host or tag; none in `ids` - all as restic mount) and next to it `latest → <folder>` (restic mount's link target: the latest snapshot's folder name, suffix included) and `latest → <short id>` (U+2192 between spaces), the same snapshot named so that the panel shows which one it is - restic mount's `latest` is a symlink, and Total Commander shows no link targets. Times are written in the snapshot's own zone by `[Settings] SnapshotTimeFormat` (placeholders `YYYY YY MM DD hh mm ss zzzz`, case-sensitive, other characters literal; at least one placeholder, at most 64 bytes, no character Windows forbids, no trailing dot or space - otherwise the default is used and logged), by default restic's colon-free template `2006-01-02_15-04-05` (`YYYY-MM-DD_hh-mm-ss`); a cached tree built with another format is not used; a name already taken gets `-1`, `-2`... (older snapshot keeps the plain name); host names and tags become one Windows-safe component (restic's `filenameFromTag` rules, plus `\ : * ? " < > \|`, control characters, trailing dots/spaces and invalid UTF-8 -> `_`, cut to 255 UTF-16 units). Folders carry the time of their newest snapshot. |
| **2. Snapshot/Subdir** | `<snapshot folder>\<SubPath>` | The snapshot's index once read (below), until then `restic ls --json --no-lock <snapshot_id> <filter_path>` | Lists direct child files and folders, populating `WIN32_FIND_DATAW` (64-bit file sizes, UTC `FILETIME` timestamps, attributes). The full 64-character snapshot ID from the tree is passed to restic. Both sources go through the same `entry_to_find_data()`, and a live test requires identical results for every folder of the fixture snapshot. |

**`snapshots.csv` (`SNAPSHOT_TREE_CSV_NAME`, `snapshot_tree_csv()`):** the repository's folder lists, after the four folders, a read-only file generated from the cached tree (no restic run of its own; it follows the tree through the same `resolve_repo_path()`, so it is refreshed with it): every snapshot with the columns `short ID`, `host`, `paths`, `size` (`summary.total_bytes_processed` as `restic snapshots` prints it, `ui.FormatBytes`: `<n> B` below 1 KiB, else three decimals of KiB/MiB/GiB/TiB rounded half to even like Go's `%.3f`, computed with integers so neither rounding nor the C locale's decimal point can differ; `0 B` for a summary without the field, empty without a summary - restic before 0.17 - or for a value that is not an exact unsigned integer), `timestamp` (`YYYY-MM-DD hh:mm:ss`, the snapshot's own clock time, which Excel reads as a date), `tags` and, last, `full ID`, sorted by host and paths ignoring ASCII case (`PC` next to `pc`), then time, then ID. Its time is when `restic snapshots` was started for the tree it comes from (`snapshot_tree_listed_at()`, set by `restic_list_snapshots()`, so also for background re-reads), in the listing and on the copy. UTF-8 with a BOM (Excel reads a BOM-less CSV in the ANSI code page), RFC 4180 records with CRLF, several paths or tags joined by LF inside one quoted field, a field quoted when it holds the separator, a quote, CR or LF (quotes doubled). Host, paths and tags are repository content: a formula character (`= + - @`, tab, CR) gets an apostrophe before it at the start of the value and after any of `, ; |` tab, LF, CR or `"` (OWASP CSV injection), so opening the file never evaluates a formula from a tag, also when a reader splits at another separator than the one written (a `CsvSeparator=;` file opened by Excel with a `,` list separator would otherwise start a cell at `x,=HYPERLINK(...)`); the fuzz target checks that no formula character follows any of those characters anywhere in the file. Excel converts short IDs like `00123456` or `123456e7` (about 3 %) to numbers and hosts like `1-2` to dates when the file is double-clicked, quoted or not (it drops the quotes first); hence the full ID in the last column, which never parses as a number (64 digits or a huge exponent stay text), and the README points to the import dialog. `="..."` would keep a short ID as text in Excel but put a formula into the data for every other reader. The separator is `[Settings] CsvSeparator` (`,` `;` `|` `tab`) or else `LOCALE_SLIST` of the user's locale (`GetLocaleInfoEx`), which is what Excel splits a double-clicked CSV at, or else `,`. The listed size is computed from the tree used for the listing; the copy (`restic_write_local_file`, the same temp-file-and-rename commit as `restic_dump_file`, overwrite protocol included) is generated from the tree cached at that moment. The name is reserved only in the repository's folder and only as the last path component (`parse_wfx_path`); a host or tag folder of that name cannot exist there, because those live under `hosts` and `tags`.

**`repository_id.txt` (`REPOSITORY_ID_FILE_NAME`):** listed after `snapshots.csv` in the repository's folder, read-only, always `REPOSITORY_ID_FILE_BYTES` (64 + 2) bytes - restic's config ID is 32 random bytes in hex, so the listing needs no restic run - and dated like `snapshots.csv` (the tree's listing time) until the ID is cached - the user did not want a file without a date; from then on the listing (`list_operation`) and every copy carry the time `restic cat config` was started for it. Its content, the ID and CRLF, comes from `restic cat config --json --no-lock` (`restic_read_repository_id()`, which accepts only 64 lowercase hex characters) on the first copy and is then kept per repository in the cache (`repo_cache_get/put_repository_id`, under the same generation rules and dropped with the password); `get_file_operation()` serves it before `resolve_repo_path()`, so it never makes restic list the snapshots. With a typed-in password the restic run also checks the password, like any other operation.

Verified against `restic mount --time-template 2006-01-02_15-04-05` of restic 0.19.1 on a repository with equal times, several hosts and tags, and tags `..` and `a/b`: identical apart from the Windows-only replacements and the added `latest → …` entries; every `latest → <folder>` names exactly the target of the corresponding `latest` symlink there.

**Whole-snapshot listings (`src/repo_cache.c`, `src/snapshot_index.c`):** after a listing inside a snapshot succeeds (or finds the path missing), `repo_cache_load_index()` starts a thread-pool worker (one snapshot per repository at a time - a second would only share its line and storage - and up to three repositories side by side; a snapshot whose load was not started is requested again by its next listing) that takes the repository's cached password (never prompts), runs `restic_list_snapshot_index()` (`ResticExecOptions.line_proc` streams stdout line by line into the index; stdout is never accumulated) and stores the finished index. The worker is cancelled through `cancel_proc` as soon as its repository is forgotten (`generation_valid_locked`: per alias, so forgetting another repository - its password timing out, say - does not touch it) and its result discarded. Memory is limited by `[Settings] SnapshotCacheMB` (default 512, 0 = off; capped at 512 MiB in 32-bit Total Commander, whose whole address space is 2 GiB): the index refuses to grow beyond it (`SNAPSHOT_INDEX_TOO_LARGE`, not retried), and while the loads grow (each worker's `cancel_proc` poll updates its share of `g_LoadingBytes`), ready indexes of other snapshots are dropped least recently used first, so kept and loading listings stay within the limit together - briefly up to half as much again while `realloc` doubles a buffer; when the loads alone need more than the limit, the one growing at that moment gives up ("set aside", `INDEX_FAILED`, tried again after a minute). A failed load is retried after 60 s at the earliest. A background `restic` that hangs is given up after 30 minutes (`BACKGROUND_TIMEOUT_MS`): a snapshot listing when no new entry arrived for that long, a snapshot-list re-read in total. The worker holds a reference to the DLL (`GetModuleHandleExW` + `FreeLibraryWhenCallbackReturns`), so `FreeLibrary` never unmaps code it runs and `DllMain` never waits for it.

**Snapshot list cache (`src/repo_cache.c`):** the tree of each repository (alias + target, and the time format it was built with) is kept in memory and answers every path it knows at once, however old (stale-while-revalidate). When a folder above the snapshots is listed from a tree older than `[Settings] SnapshotListRefreshSeconds` (default 60 s, restic mount's `minSnapshotsReloadTime`; 0 = every listing), `repo_cache_refresh_tree()` re-reads it in a background worker (one per repository, not retried sooner than that interval after a failure, the cached tree stays if it fails); the next listing shows the result. A path into a snapshot keeps meaning the snapshot it was listed for, also `latest`. Only a missing tree, a name the cached tree does not know, or an untrusted password list the snapshots while the user waits. The cache is used only with a cached (restic-verified) password; a password just typed in always goes to restic. What an operation caches with a typed-in password that ends up not kept (ESC, a timeout or a local write error before restic proved it, no memory to encrypt it) is forgotten with it (`run_with_password`, unless another thread cached a password for the repository meanwhile), and the generation is taken before the password, so a password wiped during an operation takes that operation's data along. Everything cached for a repository is dropped with its password (`session_wipe_slot_locked`: timeout, wrong password, slot recycled; `clear_password_session` -> `repo_cache_clear`: forget entry, Disconnect, `FsInitW`; `release_password_session`: DLL unload), and data read by a restic call that was running while its repository was forgotten is discarded (`repo_cache_generation`; forgetting one repository leaves the background work for the others running).

## 5. Implemented WFX API (Read-Only Browsing + File Extraction)

All exported functions use the `__stdcall` calling convention. Both Unicode (`W`) entry points and mandatory ANSI stubs are exported for full compatibility with the Total Commander plugin loader:

- **`FsInitW` / `FsInit`**
  - Stores the assigned `PluginNr` identifier and host callback pointers (`pProgressProcW`, `pLogProcW`, `pRequestProcW`).
- **`FsSetDefaultParams`**
  - Exported but empty: `DefaultIniName` is not used (see 3.1).
- **`FsGetDefRootName`**
  - Returns the root label displayed in Network Neighborhood: `[Settings] RootName` from the active INI, or `CONFIG_DEFAULT_ROOT_NAME` (`"TCResticBrowser"`) when it is missing, empty, not a valid folder name, not representable in the ANSI code page (the API is `char*`), or longer than `maxlen`. Total Commander calls it only while installing the plugin (without `FsInitW`) and stores the answer in `wincmd.ini` `[FileSystemPlugins]`, so a changed `RootName` needs the plugin to be re-added. Error dialogs (`RT_MsgOK`) use the same name as their title.
- **`FsFindFirstW` / `FsFindFirst`**
  - Initializes directory enumeration for `Path`, allocates a reentrant `ResticFindHandle`, and populates the first `WIN32_FIND_DATAW` record.
  - On empty directories, calls `SetLastError(ERROR_NO_MORE_FILES)` and returns `INVALID_HANDLE_VALUE`.
- **`FsFindNextW` / `FsFindNext`**
  - Advances the `ResticFindHandle` cursor and populates the next `WIN32_FIND_DATAW` entry, or returns `FALSE` when exhausted.
- **`FsFindClose`**
  - Frees the `ResticFindHandle` and all associated buffers.
- **`FsExecuteFileW` / `FsExecuteFile`**
  - `open` (Enter) on a root name starting with `🗑 Forget ` (the count may be stale) wipes every cached password, shows how many were remembered (`RT_MsgOK`), then sets `RemoteName` to `\` and returns `FS_EXEC_SYMLINK`: Total Commander changes to the root and re-reads it, so the entry goes away without `Ctrl+R` (the ANSI `FsExecuteFile` copies the path back into its buffer); `open` on any other file returns `FS_EXEC_YOURSELF`, so Total Commander downloads and opens it as it did before the function was exported. `properties` is a no-op (`FS_EXEC_OK`); `chmod` and `quote` are refused (`FS_EXEC_ERROR`). `MODE I`, `MODE A` and `MODE X <extensions>` - the transfer mode of the connections toolbar, an undocumented verb Total Commander sends when it is switched (and on entering a plugin) - return `FS_EXEC_OK` and change nothing: Total Commander converts nothing itself for a plugin, and `restic dump` always delivers the bytes unchanged.
- **`FsDisconnectW` / `FsDisconnect`** and the connection log (`[Settings] ConnectionLog`, default yes; `no`/`false`/`off`/`0` turns it off)
  - When a repository is first used - before its password is asked for, as an FTP plugin announces a connection when it starts connecting, so the log shows how it went - `connection_announce()` calls `LogProc(MSGTYPE_CONNECT, "CONNECT \")`: one connection for all repositories, the WFX SDK's root "for a single possible connection". Total Commander then shows its FTP connections toolbar with a log window and a Disconnect button.
  - `conn_log()` reports there, as `MSGTYPE_DETAILS` with an `[<alias>]` prefix, passwords accepted, refused and forgotten (a cached one refused by restic; a timeout and a slot recycled for another repository, both deferred through `repo_cache_report_async` because they happen with the session lock held, in the timer for the timeout), the snapshot list read in the foreground and folders listed by restic, each with its duration, and files copied as `MSGTYPE_TRANSFERCOMPLETE` `"<remote> -> <local>"` (the SDK's format).
  - Seen in Total Commander: only the user can end a connection, one per click of Disconnect, and each click switches the panel back to where it was before; `MSGTYPE_DISCONNECT` logged by the plugin changes nothing on screen. With one connection per repository (the first version) the forget entry left as many connections as repositories in use. Hence the single connection, announced only once until `FsDisconnectW` or `FsInitW` (`g_Connected`): a password that times out and the forget entry leave it listed (the forget entry says in the log that Disconnect closes the toolbar), and the next use of a repository reuses it. The forget entry still cannot close the toolbar; the first release candidate had `ConnectionLog` off by default for that reason, but the log is what explains a slow repository, so it is on by default and `ConnectionLog=no` turns it off.
  - The background work is reported there as `MSGTYPE_DETAILS`, only while connected, through `repo_cache_set_status_proc()`: `[<alias>] Reading every file and folder of snapshot <short id> in the background`, progress every 5 s (`N files and folders read so far`), the result (read with count, memory and time; larger than `SnapshotCacheMB`; not read and why), and snapshot-list re-reads.
  - The Disconnect button calls `FsDisconnectW("\")`: every password and everything cached is forgotten (`clear_password_session`, as the forget entry), `All remembered passwords and cached listings forgotten` and `MSGTYPE_DISCONNECT "DISCONNECT \"` are logged, and it returns `TRUE`; called while nothing is announced it returns `TRUE` without doing anything. The ANSI `FsDisconnect` converts from the ANSI code page.
  - `LogProc` is never called with a lock of the plugin held, nor from the password timer (its callbacks are waited for at DLL unload, and `LogProc` may wait for Total Commander's main thread); the background workers call it, holding a reference to the DLL. The timer therefore hands its message to a thread-pool worker (`repo_cache_report_async`, which holds a reference to the DLL like the other workers).
- **`FsGetFileW` / `FsGetFile`**
  - Extracts a single file from a snapshot (`restic dump --no-lock <snapshot_id> <filter_path>`) via `restic_dump_file()`, streaming Restic's stdout in 64 KB chunks (constant memory) into a **temporary file** `<target dir>\~rp<thread id>.tmp` (created with `CREATE_NEW`, so an existing file or a planted link of that name is never truncated or followed; `~rp<thread id>-<n>.tmp` is tried next) that atomically replaces `LocalName` (`MoveFileExW`) only after Restic exits with code 0. On any failure or `ESC` only the temporary file is deleted and a pre-existing target stays untouched (an interrupted overwrite never destroys the old file). The temporary file is created on the first byte, so authentication/path errors never touch the disk; 0-byte files are created at commit time. A read-only target loses the attribute only for the replacement and gets it back if the move fails.
  - Integrates with Total Commander's native copy/extract workflow: when the user copies a folder (`F5`), Total Commander walks the folder tree via `FsFindFirstW`/`FsFindNextW`/`FsFindClose`, creates the local directory hierarchy, and calls `FsGetFileW` for each file. Viewing files with `F3` (Lister) and `Ctrl+Q` (Quick View) also works automatically.
  - Implements Total Commander's two-step overwrite protocol (`FS_FILE_EXISTS` when `FS_COPYFLAGS_OVERWRITE` is not set; a read-only target is replaced when the flag is set), preserves `LastWriteTime` from `RemoteInfoStruct` (the "unknown time" marker is ignored), and reports progress to `ProgressProcW`: 0 % before the transfer, then the first chunk and at most one call per ~100 ms (capped at 99 %), 100 % on success. `ESC` -> `FS_FILE_USERABORT`. The timeout is an **inactivity** timeout (`WFX_RESTIC_TIMEOUT_MS`, 30 min without a single byte on stdout/stderr), so a slow multi-GB transfer is never killed.
  - Refuses a `LocalName` whose last component Windows cannot store under that exact name (`config_is_plain_file_name`) with `FS_FILE_WRITEERROR` and a log line, before the overwrite probe and before any password prompt: Total Commander builds `LocalName` from the snapshot name, and a name legal on Linux would otherwise write the alternate data stream `b` of the file `a` (`a:b`), a device (`CON`, `NUL.txt`, `COM1`), or the file `a` instead of `a.`. The snapshot keeps showing the original name; the user can give a single file another name in the copy dialog.
  - Result mapping: `RESTIC_ERR_LOCAL_WRITE` (disk full, missing destination directory, destination is a directory) -> `FS_FILE_WRITEERROR` without popup; `PATH_NOT_FOUND`, invalid virtual path, unknown alias, root/repository/snapshot-level path -> `FS_FILE_NOTFOUND`; cancelled or empty password dialog -> `FS_FILE_USERABORT`; wrong password after 3 attempts and other Restic failures -> `FS_FILE_READERROR` with one popup. The password session (7.5) is shared with the listing code.
  - `\<alias>\repository_id.txt` is not dumped either: `write_repository_id()` writes the ID (section 4) and CRLF the same way.
  - `\<alias>\snapshots.csv` is not dumped but generated (section 4) and written by `restic_write_local_file()` with the same temporary file, atomic replacement, overwrite protocol and mtime handling; it needs the snapshot list (cached with a trusted password, else read by restic) and so the password like any other file.
  - Rejects `FS_COPYFLAGS_MOVE` (`F6`, even combined with `OVERWRITE`) and `FS_COPYFLAGS_RESUME` with `FS_FILE_NOTSUPPORTED`; entries whose `RemoteInfoStruct.Attr` has `FILE_ATTRIBUTE_DIRECTORY` are refused too. Known limitation: Total Commander always passes `ri`, but a caller passing `ri == NULL` for a directory path would receive a tar stream (`restic dump` archives folders).

*Note:* Modification, deletion, and move functions (`FsPutFile`, `FsDeleteFile`, `FsRemoveDir`, `FsMkDir`, `FsRenMovFile`) are intentionally omitted to enforce strict read-only repository access.

## 7. Low-Level Implementation Details

### 7.1 Reentrant Search Handle (`ResticFindHandle`)

Total Commander may open directories concurrently across both panels or during recursive operations. Each `FsFindFirstW` / `FsFindNextW` cycle maintains isolated state:

```c
typedef struct {
    WIN32_FIND_DATAW* items; /* Array of entries discovered for the target path */
    size_t count;            /* Total number of entries in items */
    size_t current_index;    /* Next entry index to return in FsFindNextW */
} ResticFindHandle;
```

### 7.2 Invoking `restic.exe` via Win32 Pipes (`src/restic_cli.c`)

`restic_exec_command(exe, repo, args, options, out)` is the single process-spawning primitive; `repo` (`ResticRepo`) carries the repository target and every credential restic gets for it, so each restic call - also the background workers' - receives them the same way:

- **Executable:** must contain a path separator (bare names refused, see 3.3). The command line is built in a heap buffer sized from the inputs (limit 32767 chars, `RESTIC_ERR_INVALID_ARG` beyond it) - never in a fixed stack buffer, because `swprintf_s` aborts the host process on overflow.
- **Two pipes, two streams:** stdout and stderr use separate anonymous pipes. With `--json` stdout carries only the payload, while `{"message_type":"exit_error",...}` and warnings go to **stderr** (verified against restic 0.19.1). **Minimum restic: 0.17.1** - exit codes 10/11 and `message_type` in `ls --json` arrived in 0.17.0, exit code 12 (wrong password) in 0.17.1; older versions answer both with exit code 1. Merging them would corrupt JSON parsing whenever Restic prints a warning. The version is checked (`repository_usable()` -> `restic_version_problem()` in `main.c`) before a repository is opened and before any prompt, once per `restic.exe` file (path, size and modification time cached): `restic --json version` (`restic_read_version()`, `repo` NULL - no repository, no credentials) answers `{"message_type":"version","version":"0.19.1",...}` since 0.17.0, while older versions accept the global `--json` and print text - so output that is not that JSON is taken as older than 0.17.0 and refused (fail closed; an "unknown flag" error cannot be used, `--json` has been a global flag since 0.9), and a JSON version below `RESTIC_MIN_VERSION` is refused as well (0.17.0). A restic that cannot be started at all is left to the operation, which reports that.
- **stdin = `NUL`** so Restic can never block on an interactive prompt.
- **Explicit handle whitelist:** `STARTUPINFOEXW` + `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` makes the child inherit exactly {stdin NUL, stdout pipe, stderr pipe}, so no unrelated inheritable handle of Total Commander leaks into Restic. It does not stop a child that another Total Commander thread starts with `bInheritHandles` at the same moment from inheriting our write ends; EOF may then never arrive, which is why both output loops end when **Restic exits**, never at EOF - keep it that way. Parent-side read ends are non-inheritable.
- **Environment block** (`CREATE_UNICODE_ENVIRONMENT`): the parent environment (Go needs `SystemRoot`, `APPDATA`, `TEMP`...) minus any inherited `RESTIC_REPOSITORY`, `RESTIC_REPOSITORY_FILE`, `RESTIC_PASSWORD`, `RESTIC_PASSWORD_FILE`, `RESTIC_PASSWORD_COMMAND` (they would conflict), plus what the `ResticRepo` sets: `RESTIC_REPOSITORY` and, each only when set, `RESTIC_PASSWORD`, `RESTIC_PASSWORD_FILE`, `RESTIC_PASSWORD_COMMAND`, `AWS_SECRET_ACCESS_KEY` and the repository's `environment` block (`restic_repo_usable()` requires a target and at least one of the three password sources). When a repository has any S3 variable or secret key, every inherited `AWS_*`, `MINIO_*` and `RESTIC_AWS_*` variable is left out too: restic's S3 credential chain (static key, `AWS_*` env, `MINIO_*` env, AWS credentials file, MinIO client file, IAM) would otherwise mix Total Commander's environment into the configured credentials (an inherited `AWS_ACCESS_KEY_ID` wins over a configured credentials file); without AWS settings the environment is inherited as in 2.1, since users rely on it. The block is wiped with `SecureZeroMemory` right after `CreateProcessW`. No credential is ever placed on the command line, only the `-o` options (restic has no environment form for them); the environment also avoids a second quoting layer for `PasswordCommand`, whose value restic splits itself.
- **Output collection without deadlock:** one loop polls both pipes (`PeekNamedPipe` + `ReadFile` of up to 64 KB straight into the buffer), waits at most 20 ms on the process handle only when idle, and performs a final drain after the child exits. A pass reads at most 1 MiB per pipe, so the timeout and `ESC` are checked even while Restic floods its output. Buffers grow geometrically and are always NUL-terminated and non-NULL after a successful spawn. The stdout pipe asks for a 1 MiB buffer; reading a whole-snapshot listing 4 KB at a time made it take half again as long under Wine. With `ResticExecOptions.line_proc` set, complete stdout lines are handed over as they arrive and dropped from the buffer (`deliver_lines`), so the output never needs to fit in memory; a non-OK result from the callback stops the child. A streamed line longer than 16 MiB fails the command (`RESTIC_ERR_JSON_PARSE`), and stderr is kept up to 1 MiB (`STDERR_KEEP_BYTES`, more than any error message), the rest read and dropped, so hostile or broken output cannot fill Total Commander's memory. After the child exits, the pipes are read until they are empty, slice after slice (the stdout pipe can hold 1 MiB, a slice is 1 MiB).
- **Only Windows programs are started** (`restic_exe_startable`): before `CreateProcessW` the file must start with an `MZ` header whose `e_lfanew` points at `PE\0\0`. Anything else - a truncated download, an HTML page saved as `restic.exe`, a DOS stub - would make 64-bit Windows show its modal "Unsupported 16-Bit Application" dialog, which blocks the calling thread (Total Commander's, or a CI test run) until someone clicks it; batch files (`.bat`, `.cmd`) are refused too, because `CreateProcessW` runs them through `cmd.exe`, which does not honour the `CommandLineToArgvW` quoting of the file names taken from a snapshot. A file that cannot be opened is left to `CreateProcessW`.
- **Spawn failures** (`RESTIC_ERR_SPAWN_FAILED`: a path that is not absolute, a file that is not a Windows program, or `CreateProcessW` failing on a missing file, a file that is not a program, the wrong architecture, denied access) put `Cannot start <path>: <FormatMessage text> (Windows error N)` into the error message (`ResticCommandOutput.error_message` / `out_error_msg`) and the log, so the popup tells the user which binary failed and why. The system text is in the Windows display language.
- **Timeout and cancellation:** `ResticExecOptions { timeout_ms, cancel_proc, cancel_ctx }`. `cancel_proc` is polled about every 100 ms (intended to forward Total Commander's `ProgressProc` abort result); on timeout/cancel the child is terminated (`RESTIC_ERR_TIMEOUT` / `RESTIC_ERR_CANCELLED`) together with everything it started: `spawn_hidden()` creates restic suspended, puts it into its own job object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`contain_in_job()`) and only then resumes it, so every rclone, ssh or password command restic starts is in the job; `terminate_tree()` ends the job, closing the job handle after restic exited ends what it left behind, and Total Commander exiting (also with background restic runs) closes the handle too. Where the job cannot be made (Windows 7 inside a job without nesting) restic runs without one and only it is terminated, as before 2.2. `NULL` options mean no limit. `main.c` must always pass a cancel callback: an unreachable `rest:`/cloud repository makes Restic retry for minutes and would otherwise freeze Total Commander.
- **Exit codes:** `0` -> `RESTIC_OK`, `10` -> `RESTIC_ERR_REPO_NOT_FOUND`, `11` -> `RESTIC_ERR_REPO_LOCKED`, `12` -> `RESTIC_ERR_WRONG_PASSWORD`, anything else -> `RESTIC_ERR_CLI_FAILED`.
- **Refused storage credentials (`StderrWatch`):** restic retries a failing storage request for 15 minutes (`retry.New(be, 15*time.Minute, ...)` in restic, not configurable) and takes only S3 `AccessDenied` as permanent; a wrong secret key (`SignatureDoesNotMatch`) or an unknown key ID (`InvalidAccessKeyId`) is retried all that time with only `... returned error, retrying after ...: <reason>` lines on stderr, and Total Commander seemed to hang (reproduced with `rclone serve s3` and restic 0.19.1). Both output loops scan stderr line by line while restic runs (`watch_stderr()`): every retry line goes to `ResticExecOptions.notice_proc` (the connection log, `wfx_notice_callback`), and one whose reason is in `kRefusedCredentials` (the S3 messages and codes for a wrong signature, an unknown key ID, an expired or invalid token) ends restic with `RESTIC_ERR_CREDENTIALS_REFUSED` and that reason in the error message. `run_with_password()` then forgets a cached secret key and asks for the S3 secret key again (shared `MAX_PASSWORD_ATTEMPTS`); a repository without `AWS_ACCESS_KEY_ID` (credentials file, profile, environment) gets the message. `error_message` receives the `"message"` of the first JSON line on stderr (then stdout), or the raw trimmed text, safely truncated to 511 characters.

### 7.3 Argument Safety (`restic_list_directory`, `restic_list_snapshot_index`, `restic_dump_file`)

- Snapshot IDs go on the command line unquoted, so they are validated as hexadecimal (max 64 chars) before anything is spawned; `"--help"`, whitespace or `NULL` yield `RESTIC_ERR_INVALID_ARG`.
- The `ls` filter path (arbitrary bytes from the backed-up file system, e.g. Linux names containing a double quote) goes through `restic_quote_arg()`, which implements the `CommandLineToArgvW` escaping rules (backslashes before quotes doubled, quotes escaped). A round-trip test against `CommandLineToArgvW` covers it.
- Paths up to 1023 UTF-16 units (Total Commander's limit) are supported end to end (UTF-8 buffer of 3073 bytes).
- Known limitation: a Linux file name containing a literal backslash cannot be addressed, because the backslash is the WFX path separator. Such entries are not listed at all (see 7.4).

### 7.4 Parsing Rules (`restic_parse_*`)

- Timestamps (`restic_parse_iso8601_time`, a FILETIME wrapper around the portable `timestamp_parse`) must be complete RFC 3339 values as restic writes them: a fraction needs a digit, the zone is `Z`, `+HH`, `+HHMM` or `+HH:MM`, and nothing may follow. The calendar is checked by `timestamp.c` itself, not by `SystemTimeToFileTime`, so every platform rejects the same dates (Wine's `SystemTimeToFileTime` accepts February 29 of a common year).
- `snapshots --json` (`snapshot_tree_build`): a literal `null` is an empty list; entries without a valid time or with an ID that is not 8-64 lowercase hex characters are skipped, as is anything that is not an object. Restic gets the full 64-character ID from the tree, never a prefix, so short IDs shared by thousands of snapshots cannot make a command ambiguous. Folder names come from `SnapshotTimeFormat` applied to the time **as recorded by Restic (its own UTC offset)**, and from `hostname` and `tags` (array of strings; other elements ignored) made Windows-safe; times shown are converted to UTC `FILETIME`.
- `ls --json` of a whole snapshot (`snapshot_index_add_line`): the same strictness, line by line as restic prints it; every node must have an absolute `path`, and its parent folder must have been listed before it (restic's depth-first order), otherwise the node is ignored.
- `ls --json` NDJSON: strict - a malformed line aborts with `RESTIC_ERR_JSON_PARSE` (stdout contains JSON only). Only direct children of the filter path are returned. The filtered directory's own node is consumed to prove existence: a filter other than `/` whose node is missing or is not a `dir` yields `RESTIC_ERR_PATH_NOT_FOUND`. This distinguishes "missing" from "empty directory", which Total Commander needs (`ERROR_NO_MORE_FILES` = exists but empty, any other error = does not exist).
- Name safety (`is_safe_component`): only names that are exactly one path component are reported. Total Commander appends the reported name to build both the next virtual path and, on `F5`, the local target path, so a name containing `\` or `/` (a legal Linux file name such as `..\..\x`) would let a recursive copy write outside the chosen target directory. Names consisting only of dots and spaces (`.`, `..`, `...`, `.. `) are skipped too, because Win32 strips trailing dots and spaces from path components. Dot files and names merely ending in a dot are kept. Names legal elsewhere but not on Windows (`a:b`, `CON`, `a.`, `a?b`) are listed unchanged, so the panel shows what the backup holds; `FsGetFileW` refuses to write them (see 5).
- Entry mapping: `dir` -> `FILE_ATTRIBUTE_DIRECTORY`; everything else (files, **symlinks**, devices) -> plain file, as the WFX specification requires ("Links should be returned as files"). All entries carry `FILE_ATTRIBUTE_READONLY`. 64-bit sizes are split into `nFileSizeHigh/Low`. Times: `mtime` -> `ftLastWriteTime`, `ctime` -> `ftCreationTime` (on Linux and macOS restic's `ctime` is the inode change time, not a creation time) and `atime` -> `ftLastAccessTime`, each of the latter two falling back to `mtime` when missing; a copy gets only the modification time (`FsGetFileW` applies `RemoteInfoStruct.LastWriteTime`).
- Where every date in the panels comes from (also in the README, *Dates in the Panels*): root entries (aliases, the forget entry) none; the folders above the snapshots the newest snapshot below them, none without one; a snapshot folder (also `latest` and `latest → …`) the snapshot's time; entries inside a snapshot as above; `snapshots.csv` the start of the `restic snapshots` it comes from; `repository_id.txt` the start of `restic cat config`, until the ID is cached the time of `snapshots.csv`.
- Unknown dates: when `mtime` is missing or unparsable the entry gets Total Commander's "no date" marker (`FS_SET_TIME_UNKNOWN`: high `0xFFFFFFFF`, low `0xFFFFFFFE`); repository aliases at the root use it too.

### 7.5 Virtual Path Routing, Password Session & Host Callbacks (`src/main.c`)

- **Path decomposition (`parse_wfx_path`):** splits the backslash-delimited `Path` passed to `FsFindFirstW` into:
  - `WFX_PATH_ROOT` (`\`): calls `enumerate_root_repositories()`.
  - `WFX_PATH_REPO` (`\<RepoAlias>[\...]`): the first folder below the alias must be `hosts`, `ids`, `snapshots`, `tags`, or `snapshots.csv` or `repository_id.txt` as the last component (ASCII case-insensitive), otherwise the path is invalid before any password prompt. It resolves `RepoAlias` via `config_find_repo()`; `resolve_repo_path()` then walks the rest through the snapshot tree (section 4) to a tree folder (listed from the tree) or a snapshot ID plus the path inside it (`restic_list_directory()`, `restic_dump_file()`).
- **`run_with_password(op)`:** every repository operation (`list_operation`, `get_file_operation`) runs inside the one password loop below; a `RepoCall` tells the operation whether its password is the cached, restic-verified one (`trusted`), which is the only case in which cached data may be used.
- **Pre-flight binary check:** if `config_resolve_restic_path` did not find `restic.exe` (`cfg.restic_path` is not absolute), `restic_path_usable()` logs and displays `cfg.restic_path_error` (a configured `ResticPath` that is missing, or "restic.exe not found...") and `FsFindFirstW` / `FsGetFileW` fail (`ERROR_FILE_NOT_FOUND` / `FS_FILE_READERROR`) without prompting for a password.
- **In-memory password sessions:** `g_Sessions[8]` (`SessionSlot { alias, password }`) is guarded by an `SRWLOCK` (statically initialized, so it also works in unit tests where `DllMain` never runs) because Total Commander may call the plugin from worker threads. `run_with_password()` copies the password into a local buffer (`session_get`), runs the operation (and so Restic) **without** holding the lock, and wipes the local copy with `SecureZeroMemory`. A password is cached (`session_put`) only when restic demonstrably accepted it (`RESTIC_OK`, `REPO_LOCKED`, `JSON_PARSE`, `PATH_NOT_FOUND`: restic checks the password before it locks the repository or reads a snapshot); after a local write error, `ESC`, a timeout, a missing repository or a spawn failure an unverified password is not kept, while one cached earlier stays. `session_forget` / `clear_password_session` wipe one slot / all slots. Each `session_put` gives the slot a new `generation`; `session_get` returns it, and `session_forget` (wrong password) and `session_touch` act only if the slot still has it, so a password another thread verified in the meantime is neither wiped nor extended by mistake. A full table recycles the slot with the oldest `cached_at`. **Memory protection:** the slot table is `VirtualAlloc`ed on first use, `VirtualLock`ed (no paging), excluded from WER crash dumps (`WerRegisterExcludedMemoryBlock`, looked up at run time), and each cached password is stored as `CryptProtectMemory(CRYPTPROTECTMEMORY_SAME_PROCESS)` ciphertext; `session_get` decrypts into the caller's stack buffer, which is wiped after the restic call. If encryption fails the password is not cached; a failed lock is logged and tolerated. `release_password_session` (DLL unload) wipes, unlocks and frees the table. **Password timeout:** `[Settings] PasswordTimeoutSeconds` (default 1800, `0` = until exit, anything but a plain decimal number = default) is applied by every `load_config()`; a slot expires `cached_at` (`GetTickCount64`, which counts through sleep) + timeout after restic first accepted the password — a password taken from the cache is never `session_put` again, so use does not extend it — unless `[Settings] PasswordTimeoutResetOnUse` is yes (yes/true/on/1, default no), when `session_touch` restarts the interval after each operation completed with the cached password, also one answered from the cache without running restic (the background workers never touch it). A thread-pool timer (`session_expire_locked` re-arms it for the next expiry) wipes expired slots even while Total Commander is idle; on `FreeLibrary` it is stopped and `WaitForThreadpoolTimerCallbacks` runs outside `g_SessionLock` (the callback takes it), at process exit (`lpvReserved != NULL`) the timer is left alone and the lock is only tried (`TryAcquireSRWLockExclusive`): the other threads are already terminated, possibly one holding it. `DllMain` does not call `DisableThreadLibraryCalls`, which Microsoft advises against with the static CRT. Plain copies remain only transiently: the stack buffer during one operation, the child environment block until `CreateProcessW` returns, and restic's own process.
- **Password prompt & retry:** when no password is cached for the alias, `prompt_repository_password()` calls `RequestProcW(RT_Password)` with `ReturnedText[0] = 0` (the buffer is the dialog's default text) and the title `<alias> - Restic repository password`: password managers such as KeePassXC Auto-Type match the title of the foreground window (`GetForegroundWindow` + `GetWindowTextW`), so the alias in it selects the entry; the dialog being modal does not matter for that. An **empty** password or a cancelled dialog yields `ERROR_CANCELLED` without any popup (Restic rejects empty passwords, and accepting one would only produce a confusing generic failure). Up to `MAX_PASSWORD_ATTEMPTS` (3) prompts are shown when Restic keeps answering `RESTIC_ERR_WRONG_PASSWORD` (exit code 12); a stale cached password counts as the first attempt and is forgotten.
- **User abort (`ESC`):** `wfx_cancel_callback()` polls `ProgressProcW` every ~100 ms while Restic runs and terminates `restic.exe` on a non-zero result (`ERROR_CANCELLED`, no popup, a valid cached password is kept). Per the WFX SDK, calls made during the `FsFindFirst/Next/Close` loop are ignored by Total Commander for the first 5 seconds and only then show a progress dialog, so fast listings never flicker. The call uses `PercentDone = 0` (indeterminate) and passes the **alias, never the repository URL**, as `TargetName`: the URL can embed credentials (`rest:https://user:pass@host`) and would be shown on screen. A 30-minute `WFX_RESTIC_TIMEOUT_MS` is a safety net against hung commands.
- **Win32 error mapping:** empty listings (`RESTIC_OK` with `count == 0`) set `ERROR_NO_MORE_FILES`; missing paths or repositories set `ERROR_PATH_NOT_FOUND`; wrong passwords after retries set `ERROR_ACCESS_DENIED`; locked repositories set `ERROR_LOCK_VIOLATION`. User-facing errors are reported via both `g_LogProc(MSGTYPE_IMPORTANTERROR)` and `g_RequestProc(RT_MsgOK)`.

## 8. Compilation, Hardening & Quality Standards (MSVC `cl.exe`)

Because the plugin runs in-process inside `TOTALCMD64.EXE` and handles dynamic memory, string/JSON parsing, and external processes, strict compiler and linker practices are mandatory:

### 8.1 Strict Compiler Warning & Standard Flags
- `/TC`: Force compilation strictly as pure C (reject any C++ constructs).
- `/std:c11`: Enforce modern ISO C11 standard.
- `/permissive-`: Disable non-conforming MSVC language extensions.
- `/W4`: Enable high warning level across all project source files.
- `/WX`: Treat all warnings as errors so implicit conversions or uninitialized variables cannot slip through.
- `/we4013`: Treat implicit function declarations (missing prototypes) as errors—critical on 64-bit targets to prevent pointer truncation.

### 8.2 Static CRT Linking (`/MT` & `/MTd`)
- **Release (`/MT`):** Links the C Runtime statically into the plugin DLL. The plugin works out-of-the-box on any clean Windows installation without requiring the user to install matching *Visual C++ Redistributable* packages (`VCRUNTIME140.dll`).
- **Debug (`/MTd`):** Static Debug CRT enabling automatic heap integrity and leak checks (`_CrtCheckMemory`, `_CRTDBG_LEAK_CHECK_DF`).

### 8.3 Runtime Bug Detection & Sanitizers
- **AddressSanitizer (`/fsanitize=address /Zi`):** Detects out-of-bounds accesses, use-after-free, and double-free bugs at runtime (`build.cmd check`).
- **CRT Debug Heap (`<crtdbg.h>`):** Enabled in Debug builds (when ASan is not active) via `_CRTDBG_MAP_ALLOC` and `_CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF)`.

### 8.4 Static Analysis
- **MSVC Code Analysis (`/analyze`):** Deep data-flow inspection for `NULL` pointer dereferences, potential buffer overruns, and unchecked return values (`build.cmd check`). It covers the test programs too, warnings are errors there as well: ignoring the result of a `_Check_return_` CRT function such as `_setmode` fails the check with C6031, which a non-MSVC build does not report.
- Warnings from the SDK's own annotations are disabled where they hit, never globally: `main.c` disables C6553 because SDK 10.0.26100 annotates a `DWORD` parameter of `SetThreadpoolTimer` `_In_opt_`. Functions keep their stack below the 16 KB C6262 limit (large test buffers are `static`); `-Wstack-usage=13000` under MinGW approximates it.
- `/analyze` does not take `calloc` as initialising the members of an array of structures: freeing pointer members of such an array in a loop is C6001 ("using uninitialized memory"), while an array of plain pointers from `calloc` is fine. Keep per-item heap data in one allocation reached through an array of pointers (`SnapshotInfo` in `snapshot_tree.c`). gcc/clang do not warn; only `build.cmd check` shows it.

### 8.5 Binary Security Hardening
- **Compiler:** `/GS` (Buffer Security Check / stack cookie protection).
- **Linker:** `/DYNAMICBASE` (ASLR - Address Space Layout Randomization) and `/NXCOMPAT` (DEP - Data Execution Prevention), plus `TCResticBrowser.def` to export undecorated symbol names (on x86 the `__stdcall` entry points would otherwise be exported as `_FsInit@16` and similar).
- **Export surface:** only what `TCResticBrowser.def` lists is exported. `src/tests/test_plugin_dll.c` asserts the exact surface: only the read-only `Fs*` functions are exported; `PutFile/DeleteFile/MkDir/RemoveDir/RenMovFile/SetAttr/SetTime` (and internal helpers such as `json_parse`) must stay absent, because Total Commander enables an operation as soon as the symbol exists.
- **Imports:** only `KERNEL32.dll` and `CRYPT32.dll` (`CryptProtectMemory`, static CRT). `CMakeLists.txt` replaces CMake's default import-library list with `kernel32.lib` and names every other library on the target that needs it: `crypt32` for the plugin, `test_config` and `test_restic_cli`, plus `shell32` (`CommandLineToArgvW`) for `test_restic_cli`.

### 8.6 Build & Test Commands (`build.cmd` & `src/CMakeLists.txt`)

Windows-native only: `build.cmd` (cmd.exe + PowerShell, both part of Windows) drives CMake with the NMake generator through the pinned Visual Studio Build Tools (`.vsconfig`). No Bash, Python or other tools.

```bat
build.cmd          :: x64 + x86 Release builds, all five test programs for both, then dist\TCResticBrowser.v<version>.zip
build.cmd check    :: x64 only, no ZIP: Debug build + tests (CRT heap & leak checks), /analyze build, ASan test run
```

Every variant has its own build directory (`build\x64`, `build\x86`, `build\check-debug`, `build\check-analyze`, `build\check-asan`), so nothing needs cleaning between them. The test programs are built next to the plugin, where CMake also stages `pluginst.inf` and `TCResticBrowser.ini`; they locate those files through their own executable path and run with the repository root as the current directory (for `tmp\restic.exe`). Under ASan the plugin DLL is not built and `test_plugin_dll` reports `[SKIP]`.

**Reproducible builds:** `/Brepro /experimental:deterministic` (compiler), `/BREPRO` (linker), `/pathmap:<src>=./`, no PDB in Release, pinned toolchain (`EXPECTED_VS`, `EXPECTED_CL`, `CMAKE_T`, `CMAKE_SDK` in `build.cmd`, mirrored in `.vsconfig`; CI installs exactly the `EXPECTED_VS` Build Tools release from its fixed-version bootstrapper, SHA-256 checked, and `TCRB_VSINSTALL` makes `build.cmd` use that installation, because a Visual Studio update can service the CRT libraries and the SDK without changing the `cl.exe` version). The ZIP is made deterministic by normalizing staged text files to CRLF, writing `sha256sums.sha256`, and setting every staged timestamp to `release-date=` from `src\pluginst.inf`. Bump `version=` and `release-date=` together. After each bitness `build.cmd` runs `build-fingerprint.ps1`, which writes `build\fingerprint-<arch>.txt` (toolchain versions and hashes, the static CRT and import libraries as found in `LIB`, the generated compiler/linker options, object hashes, the DLL's Rich header and per-section hashes; machine-specific folders replaced by placeholders) and prints it; CI uploads both files. When a local and a CI build differ, `fc` of the two fingerprints shows where (CONTRIBUTING.md, *When the hashes differ*). It is a diagnostic only and never fails the build.

**Release package:** contents (all in the ZIP root, otherwise Total Commander does not detect `pluginst.inf`): `pluginst.inf`, `TCResticBrowser.wfx`, `TCResticBrowser.wfx64`, `TCResticBrowser.ini`, every repo-root Markdown file (`*.md`: README, CHANGELOG, CONTRIBUTING, AGENT, CLAUDE, LICENSE), `sha256sums.sha256`. `pluginst.inf` names the 32-bit file (`file=TCResticBrowser.wfx`); 64-bit Total Commander appends `64` itself. `type=wfx`, `defaultdir=TCResticBrowser`. The DLL is named after the project like the sibling plugins (`TCNewPlus.wfx`, `TCOfficeView.wlx`); so are the CMake target and the `.def`/`.rc`/`.ico` files in `src\`.

If Total Commander still has a freshly built DLL loaded, the link fails; run `cm_UnloadPlugins` in Total Commander (or restart it) before rebuilding.
